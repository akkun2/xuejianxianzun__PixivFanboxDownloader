# 保存投稿为 HTML

## 功能说明

插件原有的“保存投稿中的文字”功能只能生成纯文本文件。对于 FANBOX 的图文混排投稿，文字、图片和附件会被分别下载，无法保留页面中的阅读顺序。

现在可以将投稿正文保存为 HTML 文件。HTML 会按照 FANBOX 投稿数据中 `body.blocks` 的原始顺序排列以下内容：

- 普通段落
- 标题
- 图片
- 附件链接
- YouTube、Vimeo、Twitter 等嵌入资源的原始链接

正文中的粗体和行内链接也会保留。

## 使用方法

1. 打开插件的下载面板。
2. 启用“保存投稿中的文字”。
3. 在其后方选择“HTML”。
4. 按照原有方式抓取并下载投稿。

生成的 `.html` 文件继续使用“非图片的命名规则”，因此默认会和该投稿的图片、附件保存在同一个文件夹内。图片和附件的序号默认启用三位补零，例如 `001.jpeg`、`002.gif`、`003.mp4`。选择“纯文本”可以恢复原有的 `.txt` 导出方式。

## 图片与附件

HTML 中的图片优先使用下载到本地的图片，并遵循插件的“图片尺寸”设置：

- 选择“原图”时引用原图地址。
- 选择“缩略图”时引用 1200px 缩略图地址。

图片和附件仍会按照插件现有设置单独下载，HTML 导出不会改变图片类型筛选、附件筛选、命名规则或下载目录。HTML 文件及同一投稿中被 HTML 引用的图片、GIF 和附件在下载时使用同名覆盖策略，以确保 HTML 中的相对路径不会因 Chrome 自动追加序号而失效；普通 TXT、未被 HTML 引用的图片和附件下载仍使用 Chrome 默认的自动改名策略。

如果图片未被下载或被筛选，HTML 会保留安全的远程图片地址，离线打开时可能无法显示。HTML 中的本地图片按图片 ID 与下载结果关联，而不是按当前 URL 关联，因此抓取后修改“图片尺寸”设置不会使图片映射失效；文件扩展名和序号仍取自下载结果。GIF 会作为本地图片引用，MP4、MOV、AVI 等上传附件会作为当前文件夹中的本地链接引用；video 类型投稿本身仍是外部视频链接。

重复下载同一投稿的 HTML 时，HTML 和用于 HTML 的图片会覆盖下载目录中相同路径的旧文件。请在需要保留旧版本时先移动或复制旧投稿目录。

## 支持的投稿类型

- `article`：按原始 block 顺序保存图文混排内容。
- `entry`：保留原有 HTML 正文，并移除脚本、iframe、事件属性等可执行内容。
- `text`、`image`、`file`、`video`：将正文转换为 HTML，并附带相应图片、附件或视频链接。

## 与现有设置的关系

- 未启用“保存投稿中的文字”时，不会生成 HTML；“保存投稿中的外部链接”仍保持原来的 TXT 行为。
- HTML 正文中的行内链接和嵌入资源链接属于原始排版内容，会随正文保留。
- HTML 不直接插入 `urlEmbedMap` 中的 iframe 或其他外部 HTML，避免导出的文件执行不可信嵌入内容。
- 旧版本保存的设置不包含正文格式时，默认使用“纯文本”，不会改变原有使用习惯。

## 实现概要

抓取流程仍通过 FANBOX API 获取投稿详情。`article.body.blocks` 是投稿内容的有序列表，图片、附件和嵌入 block 再通过对应的 `imageMap`、`fileMap`、`embedMap` 获取资源信息。HTML 导出按一次顺序遍历完成渲染，不再从已经分离的文字和文件结果反向重建排版。

生成的 HTML 是 UTF-8 完整文档，包含投稿标题、原投稿地址和基础响应式样式，可直接使用 Chrome 等浏览器打开。
